# Database

Reference for the **Dragon Roll** data layer: PostgreSQL accessed exclusively
through Prisma. Source of truth is `prisma/schema.prisma`; this document explains
it, it does not replace it.

## How it is wired

| Piece | Location | Notes |
| --- | --- | --- |
| Schema (models, relations) | `prisma/schema.prisma` | Edit here, then create a migration. |
| Versioned migrations | `prisma/migrations/` | Applied history, newest folder = newest change. |
| Generated client | `src/generated/prisma/` | Generated by `prisma generate`. **Do not edit.** |
| Shared client instance | `lib/prisma.ts` | Server-only singleton (reused in dev via `globalThis`). |
| better-auth adapter | `lib/auth.ts` | Uses `prismaAdapter(prisma, { provider: "postgresql" })`. |

- Provider: `postgresql`. Generator output: `../src/generated/prisma`
  (`provider = "prisma-client"`).
- Connection string comes from the `DATABASE_URL` environment variable via
  `@prisma/adapter-pg` (`lib/prisma.ts`). Never expose it to the client.
- Prisma is the **only** DB access layer. All DB calls stay server-side
  (Server Actions, Server Components, better-auth); never import Prisma into a
  client component.

## Tables at a glance

Prisma model names are CamelCase; `@@map(...)` maps the auth models to
lowercase table names.

### Authentication (managed by better-auth)

| Model | Table | Purpose |
| --- | --- | --- |
| `User` | `user` | Account identity: `id`, `name`, `email` (unique), `emailVerified`, `image`, timestamps. |
| `Session` | `session` | Active login sessions: unique `token`, `expiresAt`, optional `ipAddress` / `userAgent`, `userId`. Cascade delete with the user. |
| `Account` | `account` | Provider credentials. `password` lives here (email/password login), plus optional OAuth token fields. Cascade delete with the user. |
| `Verification` | `verification` | Short-lived verification values (`identifier`, `value`, `expiresAt`). |

`User` is also the root of all game ownership (rooms, characters, monsters,
messages).

### Game domain

| Model | Purpose |
| --- | --- |
| `Room` | A game room. `code` is unique (shared invite code), `isActive`, and `createdById` → `User` (relation `RoomCreator`). |
| `RoomMember` | Membership join between `Room` and `User`. `isDM` flags the DM. `userId` is nullable to allow guests; `guestName` holds their display name. Unique per `(roomId, userId)`. |
| `Character` | A player character. `roomId` is **optional** (`onDelete: SetNull`), so characters can exist outside a room. `ownerId` → `User` (cascade). Stats: `level`, `armorClass`, `maxHp`, `currentHp`, `initiativeBonus`, and the six ability scores. |
| `MonsterTemplate` | Reusable monster/NPC stat block. Same optional `roomId` + `ownerId` pattern. No `level` or `currentHp` (only `maxHp`). |
| `Encounter` | One initiative/combat encounter inside a room: `name`, `round`, `currentTurn`, `active`. Belongs to `Room` (cascade). |
| `InitiativeEntry` | A combatant row in an encounter. `type` is `PLAYER` or `MONSTER`; links optionally to a `Character` or `MonsterTemplate`. Tracks `initiative`, `currentHp`, `maxHp`, `armorClass`, `temporaryHp`, `defeated`, `concentration`, `turnOrder`. |
| `Condition` | Status effect on an initiative entry: `name`, optional `duration`. Cascade delete with the entry. |
| `ChatMessage` | Room chat line: `message`, optional `userId` (`onDelete: SetNull`) or `guestName`. |

Enum: `CombatantType { PLAYER, MONSTER }`.

## Relations and delete behavior

- `User` → `Session`, `Account`: **cascade** (deleting a user removes their auth data).
- `User` → `Character`, `MonsterTemplate`: **cascade** (deleting a user removes their owned sheets).
- `Room` → `RoomMember`, `Encounter`, `ChatMessage`: **cascade** (deleting a room removes everything scoped to it).
- `Encounter` → `InitiativeEntry` → `Condition`: **cascade**.
- `Character` / `MonsterTemplate` → `InitiativeEntry`: **SetNull** (a deleted sheet detaches from an encounter instead of deleting combat history).
- `Character` / `MonsterTemplate` → `Room`: **SetNull** (a deleted room leaves the sheet ownerless, not deleted).
- `Room.createdBy` (`createdById`) is a required relation with **no** cascade rule — a room must always have its creator.

Indexes exist on the foreign keys used for lookups (`userId`, `roomId`,
`encounterId`, `ownerId`, `characterId`, `monsterTemplateId`, `identifier`).

## Working with the schema

```bash
npx prisma validate
npx prisma generate
npx prisma migrate dev --name migration_name   # create + apply in development
npx prisma migrate status
npx prisma studio                              # inspect data
```

Rules:
- Review migrations that can modify or delete data before running them.
- Never run `prisma migrate reset` on a database with important data.
- Never use `prisma db push` as a production substitute for reviewed migrations.
- Never modify `src/generated/prisma/` by hand; regenerate it instead.
